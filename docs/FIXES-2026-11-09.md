## 第 2 批 · 核心播放（已修）

- **20 秒断流**：删除 `AbortSignal.timeout(20000)`。`fetchGuardedAudio()` 的超时只覆盖连接 + 响应头（12s），拿到响应头即 `clearTimeout`；客户端断开时 abort 上游。实测见「验证记录」。
- **Range / 416**：`Range` 只允许 `bytes=N-M`，非法返回 `416 + Content-Range`；上游 416 原样透传 416，不再当 404。
- **上游故障伪装成无版权**：新增 `upstream_error` / `network` / `risk_control`，前端提示按 reason 分类。
- **登录态绕过本地代理**：`getTrackUrl()` 登录态也返回 `/api/audio/:id?level=…`；真实 CDN 地址只在服务端 `fetchDirectUrl()` 内部使用，不再回显客户端。
- **未知参数静默吞掉**：`level` 非白名单 → `400 BAD_LEVEL`；`fee` 非 0–16 整数 → `400 BAD_FEE`；`limit` 越界 → `400 BAD_LIMIT`；畸形 URI → `400 BAD_PARAM` 且不外泄内部错误串。
- **health 的 cookie 字段误导**：改为 `envCookie`（仅表示环境变量是否配置）+ `login` + `exposeLan`，移除旧 `cookie`。
- **静态白名单加固**：除路径前缀外再校验扩展名必须在 MIME 白名单内，`server/` 下任何文件都不会外发。

## 本次改动的副作用 / 需要你做两件事

1. **`server/.login-cookie` 被清空了，需要重新扫码登录。**
   成因：在给安全测试加状态目录隔离**之前**，测试子进程曾跑过一次 `POST /api/logout` 的黑盒断言；当时后端还是旧版（无 CSRF 校验），于是真的执行了登出并删除了本机凭据文件。该文件被 `.gitignore` 忽略、从未入库，没有备份也无法从 git 恢复。
   影响范围有限：删的是**本机保存的 `MUSIC_U` 登录凭据**，不是账号数据；云端登录态未被主动注销（旧版 logout 不通知上游），重新在侧栏扫码即可恢复。这也不是凭据泄露，方向上反而更安全。
   已做的加固：新增 `PURETONE_STATE_DIR`，`tests/security.mjs` 强制把子进程凭据指向临时目录；后续所有黑盒验证也都带该变量。已复核 `server/.logged-out` 未被写入工作区。
2. **你当前 8787 端口跑的仍是旧进程（PID 14568，双绑定 `127.0.0.1` 与 `192.168.4.12`）。**
   它仍会把无鉴权接口暴露到局域网，而且前端磁盘上已是新代码、API 却是旧后端 —— `/api/session` 会 404，导致扫码登录、退出登录、账号资料等接口因缺少令牌而失败。**请停掉并用新的 `start-server.bat` 重启**（`stop-server.bat` 现在是温和停止，不会误杀）。我没有擅自结束你正在运行的进程。
